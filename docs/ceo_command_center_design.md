# 대표 Command Center — 설계서 (v0.2, 2026-10-09)

대표(장현우) 전용 목표관리 화면 `pages/16_커맨드센터.py` 의 설계입니다.
앞으로 SCM 단계·지표를 고칠 때 이 문서와 코드를 같이 고쳐 주세요.

## 1. 원칙
1. **데이터가 들어오면 보여준다.** 값이 없으면 `0` 또는 회색 `입력/입력 대기`로 보여주고, 가짜 숫자는 만들지 않는다.
2. **재무 완료는 은행거래 매칭으로만** (AGENTS.md). 대표님의 '받음' 확인은 `cash_events` 를 바꾸지 않고 `ceo_receivable_checks` 에 따로 쌓는다.
3. **입력은 담당자가, 화면은 읽기 위주.** 계약예정·만족도·예측회의는 김선재가 팀스페이스 업무보고에서 입력하고, 이 화면은 들어온 만큼 보여준다.
4. **저장은 결정 버튼을 눌렀을 때만** (고르는 동안 저장 X, `st.form`).
5. 큰 글씨, 색은 빨강(문제)·주황(주의)·초록(정상)·파랑(정보)·회색(데이터 없음)만.
6. 이 화면에는 **별도 비밀번호를 걸지 않는다**(수정 중 불편하다는 대표님 지시). 앱 공통 `APP_PASSWORD` 만 기존처럼 적용.

### 받을 돈 로직
1. 대상: 입금 예정(`direction='in'`)이고 `paid=false`.
2. 제외: 은행거래의 `matched_cash_event_id` 로 이미 매칭된 건, 대표가 마지막으로 '받음' 확인한 건.
3. 정렬: **금액 큰 순**. 합계·건수·기한 경과(최대 경과일) 표시.
4. **체크 필요**: 대표의 확인 기록이 없거나 마지막 확인이 14일 이상 지난 건(`CHECK_EVERY_DAYS`).
5. 버튼 `✅ 받음`(received) / `⏳ 아직`(pending). '받음' 건은 합계에서 빠지고, "내가 받았다고 확인한 건"에서 되돌릴 수 있다.
6. 참고: 2026-10-09 기준 `cash_events` 에는 기한이 지난 미입금 14건(3.84억)이 남아 있다. 입금 처리가 안 된 옛 데이터일 가능성이 커서, 대표님이 하나씩 '받음/아직'을 눌러 정리하는 용도.

## 4. SCM 8단계 설계

> 바뀌지 않는 핵심 프로세스: 신규고객창출 → 고객영업 → 서비스제공(지속개선) → 만족도체크(공짜요소·시즌성) → 자동화(리소스 감축) → 재무관리(계정과목별 매출↑ 비용↓) → 개선점 조직화 → (다시 영업을 위한) IR 기획

### 4-1. 단계별 실데이터 지표
각 단계 카드 = **대표 숫자 1개 + 보조 지표 + 담당자 + ⏱ 속도(시간체크)**.

| 단계 | 대표 숫자 | 보조 지표 (DB 출처) | 팀 OKR/KPI 연결(기본 규칙) | 지금 비어 있는 데이터 |
|---|---|---|---|---|
| S1 신규고객창출 | 협상중 브랜드 수 (`sales_accounts.status`) | 최근 30일 신규 계정, 계약예정 건수·금액 (`sales_pipeline_deals`) | "신규고객" (김선재) | 계약예정 입력(김선재) |
| S2 고객영업 | 이번 달 입금 매출 (`bank_transactions` ∩ 매출 계정) | 운영중 브랜드 수, 이번 달 캠페인 등록(`sales_campaigns`), 월예산 입력 계정 | 재계약·매출·브랜드확대·상품개발·영업 | 계정별 월예산(0/8) |
| S3 서비스제공 | 업로드 완료율 (`influencer_placements.status`) | 미완료 건수, 가이드라인 확인(`guideline_ok`), 최근 14일 갱신 | 인플루언서·가이드·콘텐츠·왕홍·브랜드·캠페인·리서치·협업·알바 (곽재선·이단우) | — |
| S4 만족도체크 | 만족도 점수 입력된 계정 `n/전체` (`sales_accounts.satisfaction_score`) | 30일 넘게 접촉 없는 계정, 갱신일 30일 이내 | 고객만족 | **만족도 점수 0건, 갱신일 0건, '공짜요소·시즌성 부여' 기록 항목 자체가 없음 → 설계 필요** |
| S5 자동화 | 자동화 OKR 평균 달성률 | 개발 할 일 미완료(`dev_tasks`), 지난 KPI 기간 달성 | 시스템화·개발 미션·마진율·브랜드사관리 (구정회) | `dev_tasks` 0건 |
| S6 재무관리 | 은행거래 분류율(최근 90일) | 미분류 거래 수, 받을 돈 체크 필요, 기한 경과 미수 | 재무·정산 | 미분류 입금 147건 등 |
| S7 개선점 조직화 | 최근 14일 업무기록 건수 (`daily_activity_log`) | 대표 피드백 달린 기록, 대표 할일 완료(`assigned_tasks`), 회의록 30일, 지난 KPI 기간 달성(`okr_period_log`) | 운영루틴·업무이관·피드백·지표·성과기록·템플릿 | `okr_period_log`·`assigned_tasks` 0건 |
| S8 IR 기획 | (정의 필요) | 회사 비전 마지막 수정(`company_vision`) | IR·투자 | **IR 지표 자체가 미정 — 아래 4-4** |

### 4-2. OKR 항목 → 단계 배치
우선순위: ① 대표가 고친 항목별 배치(`ceo_scm_stage_map`, kind=okr_item) → ② 분류명별 배치(kind=category) → ③ 코드의 키워드 규칙(`KEYWORD_RULES`) → ④ 담당자 기본값(`PERSON_FALLBACK`: 김선재→S2, 곽재선·이단우→S3, 구정회→S5) → ⑤ 그래도 없으면 "단계 미지정" 경고.
화면의 `🧩 OKR 분류를 SCM 단계에 배치/수정` 에서 분류명 단위로 고칠 수 있다. 키워드 규칙은 추측이므로 대표님이 확인·수정해야 한다.

### 4-3. 신호 규칙 (시간체크)
단계에 배치된 OKR 항목(`okr_items`) 기준. 항목 상태: `done`(progress ≥ target) / `overdue`(마감일 지났는데 미달성) / `stale`(마지막 체크인이 14일 넘음 또는 없음) / `ok`.

| 신호 | 조건 |
|---|---|
| 🔴 비어있음 | 담당자 없음 + 연결된 OKR 항목 0개 |
| 🔴 막힘 | 마감 지난 미달성 항목이 1개 이상 |
| 🟠 느림 | 활성 항목 중 체크인 14일 초과(또는 없음) 비율이 50% 이상 |
| ⚪ 데이터 대기 | 연결 항목도 지표 데이터도 없음 |
| 🟢 정상 | 위에 해당 없음 |

카드 하단 ⏱ 속도 줄: `마감 지남 N · 체크인 14일↑ 없음 a/b · 가장 오래 N일`. (2026-10-09 기준 OKR 47개 중 44개가 14일 넘게 체크인 없음, 마감 지난 미달성 8개.)
속도를 "달성률 ÷ 경과 기간"으로 계산하는 방식은 항목마다 주기(weekly/monthly/once)와 누적 여부가 달라 오해를 부를 수 있어 1차에서는 쓰지 않았다. 시간체크는 **마감 초과·체크인 공백**으로만 본다.

### 4-4. 앞으로 정해야 할 것 (지속 고민)
1. **S4**: '공짜요소·시즌성 부여'를 어디에 기록할지 (예: 계정별 제공 이력 테이블 — 김선재 입력). 만족도 점수·갱신일 입력 습관 만들기.
2. **S8 IR**: 어떤 숫자를 IR 재료로 볼지 (예: 월 입금 매출, 운영 브랜드 수, 재계약률, 마진율). 1~7단계 핵심 숫자의 월별 스냅샷 저장 → IR 자료 자동 생성.
3. **S6 재무**: 계정과목별 매출↑/비용↓ — 비용 계정별 전월 대비 증감, 마진율(구정회 시스템 가동 후).
4. **S5 자동화**: '자동화로 줄인 리소스'를 어떻게 숫자로 볼지(시간/건수).
5. 담당 없는 단계(비어있음) 채우기: 박솔·미국 리드(채용예정) 배치 여부.

## 7. 알려진 제한
- 화면은 60초 캐시. 저장하면 즉시 갱신.
- `okr_items` 의 `category` 는 자유 텍스트라 단계 자동 배치는 추정이다(그래서 수정 UI가 있다).
- 받을 돈 계산은 `cash_events.paid` 가 갱신되지 않는 현재 상태를 전제로, 대표 확인 기록을 우선한다. 은행 매칭이 정착되면 '체크 필요' 건수가 자연히 줄어든다.
- 대표 전용 비밀번호는 걸지 않았다. 직원에게 URL이 공유되면 볼 수 있으므로, 필요해지면 `FINANCE_PASSWORD` 게이트를 한 줄로 추가할 수 있다.
