## 2. 목표 흐름 (대표님이 하실 일은 "올리기"와 "확인"만)
1. **기간 선택**: 예) 2026년 2기 예정(7~9월). 마감일까지 D-day 표시.
2. **자료 체크리스트**: 자료 종류별로 `✅ 자동 수집됨 / 📥 올려주세요 / ➖ 해당 없음` 상태 표시.
3. **단계별 안내**(아래 3장): 어느 사이트 → 어느 메뉴 → 어떤 파일을 받아 → 어디에 올리는지.
4. **업로드**: 파일을 올리면 형식 확인(열 이름·기간·금액 합계) 후 "N건 읽었어요, 아직 저장 전" → 확인 → 저장.
5. **검증(빠진 것 찾기)**: 은행 기간 공백, 세금계산서↔입금 미매칭, 미분류 거래 수, 해외 인플루언서 지급·PayPal 건 목록, 카드 자료 누락 월 등.
6. **패키지 만들기**: 표준 폴더·파일명으로 정리(4장).
7. **드라이브에 올리기 + 세무사 알림**(5장).

## 3. "로그인 안내" 단계 (카드사 맨날 헷갈리는 것)
- 자료별 **카드**로 보여준다: 사이트 이름·바로가기 URL·메뉴 경로·받을 파일·올릴 위치·예상 소요시간·체크박스(완료 표시).
- **아이디는 메모로 보여줄 수 있지만 비밀번호는 시스템에 저장하지 않는다**(DB에 비번 보관은 사고 시 피해가 커서 권장하지 않음 — 비번은 대표님 비밀번호 관리자에). 필요하면 "로그인 힌트(예: 대표 이메일 계정)"까지만.
- **홈택스 자동 로그인·스크래핑은 하지 않는다**(공동인증서·약관·보안). 우리는 "받은 파일을 올려서 정리"까지.
- 카드는 **홈택스에 법인카드를 등록해 두면 '신용카드 매입 조회'에서 전 카드 내역을 한 번에 받을 수 있다**(카드사별 로그인 불필요). 등록 여부 확인이 필요 → 질문 2.

## 4. 패키지(드라이브 폴더) 구조 안
```
부가세/2026-2기예정(7~9월)/
  00_요약.xlsx            ← 기간·자료 체크리스트·합계 대조·미해결 항목
  01_은행내역/            ← 계좌별·기간별(월별 시트 + 전체 원장) 엑셀 (SC제일, 기업)
  02_매출세금계산서/      ← 홈택스 원본 + 정리본
  03_매입세금계산서·계산서/
  04_카드사용내역/
  05_해외·PayPal/         ← 해외 인플루언서 지급·페이팔 자료, 영세율 증빙(해외 클라이언트 매출)
  06_인보이스·계약서/     ← 캠페인별 링크 목록(+파일)
  07_메모(세무사에게).txt ← 특이사항(상쇄 쌍, 미분류, 내부이체 등)
```
**은행내역 정리(가장 큰 일)** — 계좌별·기간별 엑셀:
- 시트: 거래원장 / 월별 입금·출금 요약 / **상쇄(결제↔취소) 제외 내역 별도 표시** / 내부이체 별도 / 미분류 목록.
- 은행 표기(날짜 형식 등) 통일. 입금·출금 합계와 기간 첫·끝 날짜 표시.
- 한계: 현재 DB에는 **잔액 열이 없어** "잔액 이어짐"으로 누락 검증은 못 한다 → 날짜 공백·건수 급감으로 의심 구간만 표시(뱅크다에서 잔액을 받을 수 있는지 확인 필요).
- 한글 엑셀 호환(utf-8-sig/xlsx) 유지.

## 5. 드라이브 올리기 — 기술 선택지
현재 서비스계정은 읽기 전용이다. 쓰려면 아래 중 하나가 필요하다.
- **A. 단계적(추천)**: 1단계는 패키지를 **ZIP/엑셀로 내려받아 대표님이 드라이브에 올림** → 2단계에서 자동 올리기 추가. 이번 10/25 마감에 가장 안전.
- **B. 대표 구글계정 연결(OAuth)**: 한 번 로그인 허용하면 대표님 드라이브(폴더)에 자동 업로드. 이미 `GOOGLE_OAUTH_CLIENT_ID/SECRET` 변수가 있음. 토큰 보관·만료 관리가 필요.
- **C. 공유 드라이브 + 서비스계정**: 세무사 공유 폴더를 공유 드라이브로 만들고 서비스계정을 멤버로 추가. 개인 드라이브 폴더는 서비스계정이 용량 문제로 업로드가 안 될 수 있음.
- 세무사 알림: Resend 메일로 폴더 링크 + 요약(대표 BCC). 세무사 접근 권한은 폴더 단위로만.

## 6. 메뉴 위치 안
- **추천**: CFO 메뉴에 새 페이지 **`VAT Filing`**(부가세 신고 준비) — 재무캘린더 상단에 "🧾 부가세 신고 준비" 바로가기 버튼(눌러서 이동). 이유: 재무캘린더가 이미 복잡하고, 신고 준비는 "기간별 작업 흐름"이라 독립 화면이 맞음.
- 대안: 재무캘린더 안에 탭 하나 추가(메뉴는 안 늘지만 재무캘린더가 더 무거워짐).

## 7. 보안·구조 주의 (대표님이 곧 DB를 나누신다고 함)
- 신고 자료에는 **급여·인건비·세금 세부**가 포함돼야 정확해진다 → 직원 앱과 같은 DB에 두지 않는다. **이 기능은 '재무 DB(개인 Supabase)' 쪽에서 돌도록** DB 연결을 설정 한 곳(환경변수)으로 모아 설계한다(분할 후 변수만 바꾸면 되게).
- 대량송금 자료가 올라오면: 급여(원천세), 4대보험, 세금 납부를 부가세 검증과 분리된 항목으로 연결(부가세 신고 자체에는 급여 불필요, 단 세무사 업무 전반엔 필요 → 폴더 분리).
- 세무사 접근은 해당 기간 폴더만. 개인 계좌·주민번호 등 불필요한 개인정보는 패키지에서 제외.

## 8. 단계별 개발 제안 (규칙 5: 동의 후 구현)
- **1단계(이번 10/25 대비, 작은 범위)**: VAT Filing 페이지 뼈대 + 기간 선택 + 자료 체크리스트 + 단계별 안내 카드 + **은행내역 계좌별·기간별 엑셀 내려받기** + 기본 검증(날짜 공백·미분류·상쇄 수). DB 변경 없음(체크 상태는 임시 → 필요 시 `vat_filing_periods` 테이블 마이그레이션 제안).
- **2단계**: 매입 세금계산서·카드(홈택스) 파일 업로드·파서, 세금계산서↔입금 매칭, 해외/PayPal 구분 목록, 요약.xlsx.
- **3단계**: 드라이브 자동 업로드 + 세무사 메일 알림 + 진행 이력(기간별 제출 상태).
- **4단계(DB 분할 후)**: 급여·원천세·4대보험 자료 연결.

## 9. 하지 않는 것
